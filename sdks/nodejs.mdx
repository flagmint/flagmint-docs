# Flagmint JavaScript SDK

The Flagmint JavaScript SDK evaluates feature flags in browsers and Node.js. After `ready()`, `getFlag()` reads a local snapshot — there is no network on the read path. Flag publishes arrive over Server-Sent Events (SSE).

## Key Features

- **Framework-agnostic** — React, Vue, Angular, vanilla JS, Express, Fastify, and Node.js
- **SSE streaming** — Handshake at `POST /auth/asl-handshake`, flags at `GET /evaluator/v2/flags/stream`
- **Automatic reconnection** — A consumed `sessionId` is single-use; reconnects fetch a new one
- **Long-polling fallback** — `transportMode: 'auto'` tries SSE, then `POST /evaluator/evaluate`
- **Pluggable caching** — localStorage in the browser; inject Redis or files in Node
- **Type-safe** — TypeScript declarations included

<Note>
  v2 replaces WebSocket with SSE. Use `transportMode: 'sse' | 'long-polling' | 'auto'`. The `'websocket'` option is no longer valid.
</Note>

## Quick Start

### Browser

```javascript
import { FlagClient } from 'flagmint-js-sdk';

const client = new FlagClient({
  apiKey: 'ff_your_api_key_here',
  enableFlagmint: true,
  context: {
    kind: 'multi',
    user: {
      kind: 'user',
      key: 'user123',
      email: 'user@example.com'
    },
    organization: {
      kind: 'organization',
      key: 'org456',
      plan: 'premium'
    }
  },
  onError: (error) => {
    console.error(error.message, error.code);
  }
});

await client.ready();

const showBanner = client.getFlag('show_banner', false);
const featureVersion = client.getFlag('feature_version', 'v1');
```

Same-origin tabs and iframes that share an API key use **one** SSE connection when `BroadcastChannel` is available. Set `shareConnection: false` if two clients on the page must keep different evaluation contexts, or if the origin hosts untrusted documents.

### Node.js

```bash
npm install eventsource
```

```javascript
import { FlagClient } from 'flagmint-js-sdk';
import EventSource from 'eventsource';

const apiKey = process.env.FLAGMINT_API_KEY;
if (!apiKey) {
  throw new Error('FLAGMINT_API_KEY is required');
}

const client = new FlagClient({
  apiKey,
  enableFlagmint: true,
  EventSourceImpl: EventSource,
  env: process.env.FLAGMINT_ENVIRONMENT || 'production',
  onError: (error) => {
    console.error('Flagmint error:', error);
  }
});

await client.ready();

const enabled = client.getFlag('new_api', false);
```

Each Node process (including each cluster worker) should construct its own `FlagClient`. Connection sharing is off without `window`.

<Warning>
  **`ready()` never throws.** Auth, quota, and transport failures go to `onError`. If a cache snapshot exists, `getFlag()` keeps serving it. Always set `onError` in production.
</Warning>

## How it works

After `ready()`:

1. Optionally joins a same-origin share group (browser). Followers skip handshake and the stream.
2. `POST /auth/asl-handshake` with `X-API-Key` → single-use `sessionId` (5 minute TTL).
3. Opens `GET /evaluator/v2/flags/stream?sessionId&context&sdkVersion&platform&wrapper*`.
4. The server sends `connected` (connection id) then `flags` (evaluated map). Heartbeats are SSE comments (`: heartbeat`) and are not exposed by EventSource.
5. Flags are stored in the cache adapter. Later dashboard publishes arrive as `flags` events on the same stream.

`getFlag()` / `getFlags()` never hit the network. They read the last evaluated snapshot.

`updateContext()` posts `/evaluator/v2/flags/context` with `x-api-key` and a JSON body of `connectionId` plus `context`. The HTTP response is `202`; new values arrive as a `flags` event after a **400ms** server debounce.

See the [streaming evaluation API](/api-reference/evaluate) for the wire protocol.

<Warning>
  The stream URL serializes `context` as a base64 query parameter. Do not put secrets or PII in context. Redact `sessionId` and `context` from access logs, reverse-proxy logs, and telemetry.
</Warning>

## Configuration

### FlagClientOptions

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `apiKey` | `string` | **Required** | Environment API key (`ff_…`) |
| `enableFlagmint` | `boolean` | `true` | Set `false` in local/dev to skip handshake and the stream |
| `context` | object | empty object | Initial evaluation context. Do not put secrets or PII here |
| `transportMode` | `auto`, `sse`, or `long-polling` | `auto` | `auto` tries SSE, then long-polling |
| `EventSourceImpl` | EventSource constructor | browser global | **Required in Node** |
| `shareConnection` | `boolean` | `true` in browsers with `BroadcastChannel`, `false` in Node | One stream per API key across same-origin documents |
| `enableOfflineCache` | `boolean` | `true` | Load/save flags via the cache adapter |
| `persistContext` | `boolean` | `false` | Persist context in the cache adapter |
| `cacheAdapter` | `CacheAdapter` | localStorage helpers | Custom cache (Redis, files, and similar) |
| `restEndpoint` | `string` | env default | Override the long-polling / evaluate URL |
| `sseEndpoint` | `string` | env default | Override the SSE base URL (`/stream` and `/context`) |
| `handshakeEndpoint` | `string` | env default | Override the ASL handshake URL. Use with `sseEndpoint` for self-hosted gateways |
| `env` | `string` | `NODE_ENV` | `development`, `staging`, or `production` |
| `wrapperInfo` | object with `name` and `version` | native-js | Framework wrapper telemetry on the stream URL |
| `previewMode` / `rawFlags` | — | — | Local-only evaluation, no network |
| `deferInitialization` | `boolean` | `false` | Wait for `ready()` before connecting |
| `debugLog` | `boolean` | `false` | Verbose SDK logs |
| `onError` | callback | — | Auth, quota, transport, and context errors. `ready()` still resolves |

<Note>
  **Endpoint auto-detection** uses `env` (or `NODE_ENV`): production → `api.flagmint.com`, staging → `staging-api.flagmint.com`, development → `localhost:3000`. Override with `restEndpoint`, `sseEndpoint`, and `handshakeEndpoint` for self-hosted gateways.
</Note>

## Cache Adapters

### Sync (Browser / In-Memory)

By default, the SDK uses a sync `localStorage`-based helper in browsers:

```javascript
import { FlagClient } from 'flagmint-js-sdk';
import { setCacheStorage } from 'flagmint-js-sdk/core/cacheHelper';

const myMap = new Map();
setCacheStorage({
  getItem: (key) => myMap.get(key) ?? null,
  setItem: (key, val) => myMap.set(key, val),
});

const client = new FlagClient({
  apiKey: 'ff_...',
  enableFlagmint: true,
  enableOfflineCache: true
});
```

### Async (Redis / File System)

Use the async helper for server-side or React Native:

```javascript
import { FlagClient } from 'flagmint-js-sdk';
import * as asyncCache from 'flagmint-js-sdk/core/cacheHelper.async';
import EventSource from 'eventsource';

const client = new FlagClient({
  apiKey: 'ff_...',
  enableFlagmint: true,
  EventSourceImpl: EventSource,
  cacheAdapter: {
    loadFlags: asyncCache.loadCachedFlags,
    saveFlags: asyncCache.saveCachedFlags,
    loadContext: asyncCache.loadCachedContext,
    saveContext: asyncCache.saveCachedContext
  }
});
```

### Custom Cache (Redis Example)

```javascript
import { FlagClient } from 'flagmint-js-sdk';
import EventSource from 'eventsource';
import redis from 'redis';

const redisClient = redis.createClient();

const client = new FlagClient({
  apiKey: 'ff_...',
  enableFlagmint: true,
  EventSourceImpl: EventSource,
  cacheAdapter: {
    loadFlags: async (apiKey, cacheTTL) => {
      const cached = await redisClient.get(`flags:${apiKey}`);
      if (!cached) return null;
      const parsed = JSON.parse(cached);
      return parsed;
    },
    saveFlags: async (apiKey, flags) => {
      await redisClient.setex(
        `flags:${apiKey}`,
        600,
        JSON.stringify(flags)
      );
    },
    loadContext: async (apiKey) => {
      const cached = await redisClient.get(`context:${apiKey}`);
      return cached ? JSON.parse(cached) : null;
    },
    saveContext: async (apiKey, context) => {
      await redisClient.setex(
        `context:${apiKey}`,
        3600,
        JSON.stringify(context)
      );
    }
  }
});
```

<Note>
  The default cache TTL is 24 hours. `loadFlags` receives the TTL in milliseconds so a custom adapter can respect it.
</Note>

## Transport Modes

| Mode | Behaviour | Best for |
|------|-----------|----------|
| **SSE** | Persistent `text/event-stream`. Failures go to `onError`; cached flags keep serving (no long-polling fallback) | Node servers, browsers that allow EventSource |
| **Long-polling** | `POST /evaluator/evaluate` on a 20-minute interval, exponential backoff on failure (up to 60s, 2× multiplier) | Firewalls that block EventSource, serverless |
| **Auto** (default) | Tries SSE first, then long-polling | Most applications |

```javascript
const client = new FlagClient({
  apiKey: 'ff_...',
  enableFlagmint: true,
  transportMode: 'sse' // or 'long-polling' or 'auto'
});
```

## Connection sharing

Used when the same app is embedded twice on one origin (for example two iframes in a host page).

- **Leader** performs handshake and holds EventSource.
- **Followers** receive flag snapshots over `BroadcastChannel` (`flagmint-share` plus the API key). Leadership is a `localStorage` lock.
- Follower `updateContext()` is forwarded to the leader. Last write wins.
- If the leader iframe unloads, it posts `bye` so another member can take over. If the tab is killed without `pagehide`, followers wait for the lock TTL.

```javascript
shareConnection: true   // default in browsers with BroadcastChannel
shareConnection: false  // two clients, two contexts, two streams
```

Node cluster workers do not share. Each worker process opens its own stream.

Turn sharing off if you host untrusted content on the same origin — any same-origin document can send the context RPC and read the flags that come back.

## Framework Integration Examples

### Node.js / Express

```javascript
import { FlagClient } from 'flagmint-js-sdk';
import EventSource from 'eventsource';
import * as asyncCache from 'flagmint-js-sdk/core/cacheHelper.async';

const client = new FlagClient({
  apiKey: process.env.FLAGMINT_API_KEY,
  enableFlagmint: true,
  EventSourceImpl: EventSource,
  cacheAdapter: {
    loadFlags: asyncCache.loadCachedFlags,
    saveFlags: asyncCache.saveCachedFlags,
    loadContext: asyncCache.loadCachedContext,
    saveContext: asyncCache.saveCachedContext
  },
  onError: (err) => console.error('Flagmint error:', err)
});

await client.ready();

app.get('/api/feature', (req, res) => {
  const isEnabled = client.getFlag('new_api', false);
  res.json({ enabled: isEnabled });
});
```

<Warning>
  `updateContext()` changes **that connection’s** context. It is the right tool for a browser user logging in. It is the wrong tool for many concurrent Node HTTP requests with different targeting on one singleton client — wait for client-side rule evaluation, or use a dedicated client per distinct context.
</Warning>

### React

```javascript
import { useEffect, useState } from 'react';
import { FlagClient } from 'flagmint-js-sdk';

const client = new FlagClient({
  apiKey: 'ff_...',
  enableFlagmint: true,
  context: {
    kind: 'multi',
    user: { kind: 'user', key: 'user123', email: 'user@example.com' }
  },
  onError: (err) => console.warn(err.message)
});

export function App() {
  const [flags, setFlags] = useState({});
  const [ready, setReady] = useState(false);

  useEffect(() => {
    const unsubscribe = client.subscribe((updatedFlags) => {
      setFlags({
        showBeta: updatedFlags['show_beta'] ?? false,
        theme: updatedFlags['theme'] ?? 'light'
      });
    });

    client.ready().then(() => setReady(true));

    return () => {
      unsubscribe();
    };
  }, []);

  if (!ready) return <div>Loading...</div>;

  return (
    <div className={'theme-' + flags.theme}>
      {flags.showBeta && <BetaFeature />}
    </div>
  );
}
```

<Note>
  Prefer [`flagmint-react-sdk`](/sdks/react) in React apps. Wrappers construct `FlagClient` for you. Connection sharing lives in this core SDK, not in the wrappers.
</Note>

## Context Management

```javascript
await client.updateContext({
  kind: 'multi',
  user: {
    kind: 'user',
    key: 'user123',
    email: 'user@example.com',
  },
  organization: {
    kind: 'organization',
    key: 'org456',
    plan: 'premium',
    country: 'CA'
  }
});
```

Await this call. The promise settles when the stream delivers the next `flags` packet (or times out and keeps the previous snapshot). Overlapping calls are serialized.

If the transport is unavailable, the context is still updated locally but flags will not reflect the change until the connection is restored.

## Error Handling

Failures are reported through `onError`, never thrown from `ready()`.

| `error.code` | Meaning |
|---|---|
| `ERR_AUTH` | Invalid API key, missing session, inactive subscription |
| `ERR_RATE_LIMITED` | Evaluation quota exceeded. Check `retryAfter` (seconds) and `resetTime`. Free-tier payloads may include a last snapshot in `data`; the SDK applies it and keeps serving cache |
| `ERR_INVALID_CONTEXT` | Stream rejected the context payload |
| `ERR_INTERNAL` | Named SSE `error` from the server |

```javascript
const client = new FlagClient({
  apiKey: 'ff_...',
  enableFlagmint: true,
  onError: (error) => {
    const { code, retryAfter, resetTime, message } = error;
    console.error(code, message, retryAfter, resetTime);
  }
});

await client.ready();
```

`transportMode: 'sse'` does not fall back to long-polling; it stays on the last cached snapshot (if any). `auto` tries SSE, then long-polling.

### Offline resilience

| Scenario | `ready()` | `getFlags()` | `onError` |
|----------|-----------|-------------|-----------|
| Transport succeeds | Resolves | Fresh flags | Not called |
| Transport fails, cache exists | Resolves | Cached flags | Called |
| Transport fails, no cache | Resolves | `{}` (empty) | Called |
| Transport fails, cache expired (>24h) | Resolves | `{}` (empty) | Called |

### Subscribing to flag updates

```javascript
const unsubscribe = client.subscribe((flags) => {
  console.log('Flags updated:', flags);
});

unsubscribe();
```

The callback fires immediately with current flags (including cache), then on every push. `destroy()` clears subscribers.

## API Reference

### FlagClient Methods

#### `ready(timeoutMs)`

Wait for initial connection and flag synchronisation. Always resolves. Default timeout is 3000ms.

```javascript
await client.ready();
await client.ready(5000);
```

When `deferInitialization` is `true`, calling `ready()` triggers initialization.

#### `getFlags()`

Get all current flag values as a shallow copy.

```javascript
const allFlags = client.getFlags();
```

#### `getFlag(key, fallback)`

Get a single flag value with an optional fallback.

```javascript
const theme = client.getFlag('theme', 'light');
const showFeature = client.getFlag('new_feature', false);
```

#### `updateContext(context)`

Merge new context with the existing context. On SSE, posts `/evaluator/v2/flags/context` and waits for the next `flags` event.

```javascript
await client.updateContext({
  user: { key: 'user456', email: 'newuser@example.com' }
});
```

#### `subscribe(callback)`

Subscribe to flag changes. Fires immediately, then on every update. Returns an unsubscribe function.

```javascript
const unsubscribe = client.subscribe((flags) => {
  console.log('Current flags:', flags);
});

unsubscribe();
```

#### `destroy(): void`

Close the transport, clear subscribers, and leave any share group.

```javascript
client.destroy();
```

#### `trackError(flagKey, error?, extra?)`

Send an error event attributed to a flag. Feeds the [Guardrails](/concepts/guardrails) error-rate pipeline.

```javascript
client.trackError('my_flag', err, { step: 'checkout' });
```

#### `track(flagKey, eventName, extra?)`

Send a custom analytics event attributed to a flag. Appears in the flag's analytics panel.

```javascript
client.track('my_flag', 'checkout_completed', { orderId: 'ord_123' });
```

### CacheAdapter Interface

```typescript
interface CacheAdapter<C = any> {
  loadFlags(apiKey: string, cacheTTL: number): Promise<Record<string, any>> | Record<string, any> | null;
  saveFlags(apiKey: string, flags: Record<string, any>): Promise<void> | void;
  loadContext(apiKey: string): Promise<C | null> | C | null;
  saveContext(apiKey: string, context: C): Promise<void> | void;
}
```

## Analytics & Guardrails

<Note>
  `trackError` and `track` are available from **flagmint-js-sdk 2.0.0**. Support for the Go SDK and others is coming soon.
</Note>

The SDK exposes two methods for sending application events back to Flagmint. Both require **Analytics Tracking** to be enabled for the flag in the dashboard, and both are no-ops when `enableFlagmint: false` or `previewMode: true`.

### `trackError(flagKey, error?, extra?)`

Records an error event attributed to `flagKey`. This is what feeds [Guardrails](/concepts/guardrails) — every call increments the error count for that flag in the current time bucket. Use it inside catch blocks that handle code paths gated by a feature flag.

```javascript
const newCheckout = client.getFlag('new_checkout_flow', false);

try {
  await processPayment();
} catch (err) {
  client.trackError('new_checkout_flow', err, { step: 'payment' });
  throw err;
}
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `flagKey` | `string` | The flag key to attribute this error to |
| `error` | `unknown` | Optional. `name` and `message` are extracted (max 500 chars each). Stack traces are never sent. |
| `extra` | `Record<string, unknown>` | Optional. Additional context — order IDs, request IDs, etc. |

The variation value and user key are captured automatically from the SDK's current state at call time.

### `track(flagKey, eventName, extra?)`

Records a custom event attributed to `flagKey`. Use this for conversion tracking, user actions, and A/B test outcomes. Custom events appear in the flag's analytics panel but do **not** count toward the guardrail error rate.

```javascript
// Successful checkout — record it as a custom event
client.track('new_checkout_flow', 'checkout_completed', {
  orderId: 'ord_abc123',
  amount: 49.99,
});
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `flagKey` | `string` | The flag key to attribute this event to |
| `eventName` | `string` | A name for this event type, e.g. `'checkout_completed'` |
| `extra` | `Record<string, unknown>` | Optional. Any additional data to attach |

### Event batching

Both methods are fire-and-forget:

- Events are queued in memory and flushed every **2 seconds** (or when 20 events accumulate, whichever comes first).
- They never throw — errors in the event pipeline are silently swallowed to prevent application impact.
- Events are sent to `POST /evaluator/events` using the same API key as the SDK connection.

<Note>
  Only `trackError` calls count toward a flag's error rate and can trigger a Guardrail. `track` events are for analytics only. See [Guardrails](/concepts/guardrails) for threshold configuration and auto-pause behaviour.
</Note>

## Troubleshooting

### Client not connecting

- Verify the API key (`ff_…`) and that `enableFlagmint` is `true`
- In Node, pass `EventSourceImpl` (for example `eventsource`)
- Check `onError` for `ERR_AUTH` or `ERR_RATE_LIMITED`
- Ensure CORS allows your origin if you are in a browser

### Flags not updating

- Confirm `transportMode` is `'auto'` or `'sse'`
- Call `updateContext()` after login and await it
- Use `subscribe()` to listen for pushes
- If using a custom cache adapter, verify TTL is not too aggressive

### `ready()` resolved but flags are empty

- `onError` was likely called — check the code (`ERR_AUTH`, `ERR_RATE_LIMITED`)
- Cache may be empty or expired (>24h)
- `enableFlagmint: false` skips the network entirely

### Node cluster / multiple processes

- Each worker needs its own `FlagClient` and EventSource connection
- Do not share one client across forked processes
- Do not call `updateContext()` per HTTP request on a singleton client

### Performance

- Prefer SSE for long-running servers (one stream, pushes on publish)
- Use long-polling for short-lived serverless invocations
- Use Redis as `cacheAdapter` when you need a shared snapshot across workers
