The Flagmint React SDK provides hooks for evaluating feature flags in React and Next.js applications. Flags update in real-time via SSE (Server-Sent Events).

<Note>
  **v1.2.1+** uses `transportMode: 'sse'`. If you are on an older version, use `'websocket'` instead.
</Note>

## Installation

<CodeGroup>

```bash npm
npm install flagmint-react-sdk
```

```bash yarn
yarn add flagmint-react-sdk
```

```bash pnpm
pnpm add flagmint-react-sdk
```

</CodeGroup>

## Setup

### Add the Provider

`FlagmintProvider` initialises the SDK and provides flag context to all child components. Place it as high as possible in your component tree.

<CodeGroup>

```tsx Next.js (App Router)
// app/providers.tsx
'use client';
import { FlagmintProvider } from 'flagmint-react-sdk/client';

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <FlagmintProvider
      options={{
        apiKey: process.env.NEXT_PUBLIC_FLAGMINT_KEY!,
        transportMode: 'sse',
      }}
    >
      {children}
    </FlagmintProvider>
  );
}
```

```tsx Vite
// main.tsx
import { FlagmintProvider } from 'flagmint-react-sdk/client';

ReactDOM.createRoot(document.getElementById('root')!).render(
  <FlagmintProvider
    options={{
      apiKey: import.meta.env.VITE_FLAGMINT_KEY,
      transportMode: 'sse',
    }}
  >
    <App />
  </FlagmintProvider>
);
```

</CodeGroup>

<Note>
  Configuring `enableOfflineCache` and `persistContext`? See [SDK Privacy and Caching Configuration](/sdks/privacy-and-caching) for consent-aware setup guidance and legal/compliance mapping.
</Note>

<Warning>
  Do not place `FlagmintProvider` inside a nested layout or page component. Doing so creates a new SSE connection on every route navigation.
</Warning>

### Provider Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `options` | `FlagClientOptions` | Required | SDK configuration (see below) |
| `initialFlags` | `Record<string, any>` | `{}` | Pre-evaluated flags for SSR hydration |
| `deferInitialization` | `boolean` | `false` | If true, don't connect until context is set |

### FlagClientOptions

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `apiKey` | `string` | Required | Your environment's SDK key (starts with `ff_`) |
| `context` | `object` | `undefined` | Evaluation context (user, org attributes) |
| `transportMode` | `'auto' \| 'sse' \| 'long-polling'` | `'auto'` | Connection method (`'websocket'` in versions prior to 1.2.1) |
| `enableOfflineCache` | `boolean` | `true` | Cache flags in localStorage for offline use |
| `persistContext` | `boolean` | `false` | Persist context across page reloads |
| `onError` | `(error: Error) => void` | `undefined` | Error handler callback |

## Evaluating Flags

### useFlag

Returns the evaluated value of a single flag. Re-renders the component when the flag value changes.

```tsx
import { useFlag } from 'flagmint-react-sdk/client';

// Boolean flag
const showFeature = useFlag<boolean>('new-feature', false);

// String flag
const buttonColor = useFlag<string>('button-color', 'blue');

// Number flag
const maxItems = useFlag<number>('max-items', 10);

// JSON flag
const config = useFlag<{ retries: number }>('api-config', { retries: 3 });
```

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `key` | `string` | The flag key (must match the key in the dashboard) |
| `defaultValue` | `T` | Fallback value used when the SDK isn't ready or the flag doesn't exist |

### useFlagmintReady

Returns `true` once the SDK has connected and received its initial flag values.

```tsx
import { useFlag, useFlagmintReady } from 'flagmint-react-sdk/client';

export function Feature() {
  const isReady = useFlagmintReady();
  const showFeature = useFlag<boolean>('new-feature', false);

  if (!isReady) return <LoadingSpinner />;
  if (!showFeature) return null;

  return <NewFeature />;
}
```

<Tip>
  Use `useFlagmintReady` to prevent a flash of default content before flags load. For pages that work fine without flags (login, signup), skip the ready check and let children render immediately.
</Tip>

## User Context

### Setting Context at Init

Pass context when the user is known (typically after login):

```tsx
<FlagmintProvider
  options={{
    apiKey: process.env.NEXT_PUBLIC_FLAGMINT_KEY!,
    context: {
      kind: 'multi',
      user: {
        kind: 'user',
        key: user.id,
        email: user.email,
        country: user.country,
      },
      organization: {
        kind: 'organization',
        key: user.orgId,
        plan: user.plan,
      },
    },
  }}
>
```

### Authentication Pattern

The recommended pattern for apps with login is to always render children, but only pass context after authentication:

```tsx
'use client';
import { FlagmintProvider } from 'flagmint-react-sdk/client';
import { useUser } from '@/hooks/useUser';

export function FlagmintWithAuth({ children }: { children: React.ReactNode }) {
  const { user, isLoading } = useUser();

  const apiKey = process.env.NEXT_PUBLIC_FLAGMINT_KEY;
  if (!apiKey) return <>{children}</>;

  // Not logged in yet — render without flags
  if (!user || isLoading) return <>{children}</>;

  return (
    <FlagmintProvider
      options={{
        apiKey,
        transportMode: 'sse',
        context: {
          kind: 'multi',
          user: { kind: 'user', key: user.id, email: user.email },
          organization: { kind: 'organization', key: user.orgId, plan: user.plan },
        },
      }}
    >
      {children}
    </FlagmintProvider>
  );
}
```

This ensures public pages (login, signup, marketing) render immediately without waiting for the SDK.

## Transport Modes

| Mode | Best For | Real-Time? |
|------|----------|-----------|
| `sse` | Browser apps, dashboards | Yes — server pushes updates instantly |
| `long-polling` | Server-side rendering, restricted networks | No — polls every 10 seconds |
| `auto` | Most apps (default) | Tries SSE, falls back to polling |

For client-side React apps, `sse` is recommended. The SDK maintains a single persistent connection and receives flag updates the moment they change in the dashboard.

## Offline & Caching

When `enableOfflineCache` is `true` (the default), the SDK caches flag values in `localStorage`. If the server is unreachable on the next page load, the SDK serves cached values until a connection is re-established.

Cached values expire after 24 hours.

## TypeScript

The SDK is fully typed. Use generics with `useFlag` to get type-safe flag values:

```tsx
interface FeatureConfig {
  maxRetries: number;
  timeout: number;
  enableLogging: boolean;
}

const config = useFlag<FeatureConfig>('api-config', {
  maxRetries: 3,
  timeout: 5000,
  enableLogging: false,
});

// config is typed as FeatureConfig
console.log(config.maxRetries); // ✓ type-safe
```

## Analytics & Guardrails

<Note>
  `trackError` and `track` are available from **flagmint-react-sdk 1.2.1**. Support for the Go SDK and others is coming soon.
</Note>

The `useFlagmint()` hook exposes `trackError` and `track` for sending application events back to Flagmint. Both require **Analytics Tracking** to be enabled for the flag in the dashboard.

### `trackError`

Records an error event attributed to a flag. This is the signal that feeds [Guardrails](/concepts/guardrails) — every call increments the error count for that flag's time bucket. Place it inside the catch block of code gated by a feature flag.

```tsx
import { useFlag, useFlagmint } from 'flagmint-react-sdk/client';

export function Checkout() {
  const showNewFlow = useFlag<boolean>('new_checkout_flow', false);
  const { trackError } = useFlagmint();

  const handleSubmit = async () => {
    try {
      await processPayment();
    } catch (err) {
      trackError('new_checkout_flow', err, { step: 'payment' });
      throw err;
    }
  };

  return showNewFlow ? <NewCheckout onSubmit={handleSubmit} /> : <LegacyCheckout />;
}
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `flagKey` | `string` | The flag key to attribute this error to |
| `error` | `unknown` | Optional. `name` and `message` are extracted (max 500 chars each). Stack traces are never sent. |
| `extra` | `Record<string, unknown>` | Optional. Additional context — order IDs, request IDs, etc. |

### `track`

Records a custom analytics event attributed to a flag. Use this for conversion tracking, user actions, and A/B test outcomes. Custom events appear in the flag's analytics panel but do **not** count toward the guardrail error rate.

```tsx
import { useFlag, useFlagmint } from 'flagmint-react-sdk/client';

export function CheckoutSuccess() {
  const { track } = useFlagmint();

  useEffect(() => {
    track('new_checkout_flow', 'checkout_completed', { orderId: 'ord_abc123' });
  }, []);

  return <SuccessScreen />;
}
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `flagKey` | `string` | The flag key to attribute this event to |
| `eventName` | `string` | A name for this event type, e.g. `'checkout_completed'` |
| `extra` | `Record<string, unknown>` | Optional. Any additional data to attach |

### Behaviour

Both methods are fire-and-forget — they never throw and never cause a re-render. Events are batched and flushed every 2 seconds. If analytics is disabled for the flag or the SDK is in preview mode, calls are silently dropped.

<Note>
  Only `trackError` counts toward a flag's error rate and can trigger a Guardrail. `track` is for analytics only. See [Guardrails](/concepts/guardrails) for threshold configuration and auto-pause behaviour.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="useFlagmintReady always returns false">
    The SDK can't connect to the server. Check that your API key is correct, the API URL is reachable, and CORS allows your app's origin.
  </Accordion>
  <Accordion title="Flags don't update in real-time">
    Verify you're using `transportMode: 'sse'` (or `'websocket'` if on a version prior to 1.2.1). If you're behind a corporate proxy that blocks SSE connections, switch to `'long-polling'`.
  </Accordion>
  <Accordion title="Hydration mismatch in Next.js">
    The server doesn't have flag values during SSR. Use the `initialFlags` prop to pass pre-evaluated flags, or wrap the flag-dependent UI with `useFlagmintReady` to defer rendering until the client has connected.
  </Accordion>
  <Accordion title="SSE disconnects and reconnects repeatedly">
    Check your server's heartbeat interval. The SDK sends a heartbeat every 25 seconds. If your proxy or server closes idle connections before that, switch to `'long-polling'` or increase the server-side keep-alive timeout.
  </Accordion>
  <Accordion title="CORS error when connecting">
    Your Flagmint API must include your app's origin in its CORS configuration. For local development, ensure `localhost:3000` (or your dev port) is allowed.
  </Accordion>
</AccordionGroup>
