The **JavaScript SDK v2** uses handshake + SSE. The **Go SDK** still uses WebSocket at `/ws/sdk`. REST evaluate remains the one-shot and long-polling path.

## Evaluate Flags

<ParamField body="context" type="object" required>
  The evaluation context containing user and/or organisation attributes. Targeting rules match against this context.
</ParamField>

### Request

```bash
POST /evaluator/evaluate
x-api-key: ff_your_sdk_key
Content-Type: application/json
```

```json
{
  "context": {
    "kind": "multi",
    "user": {
      "kind": "user",
      "key": "user-123",
      "email": "alice@example.com",
      "country": "IE",
      "plan": "pro"
    },
    "organization": {
      "kind": "organization",
      "key": "org-456"
    }
  }
}
```

### Response

```json 200 OK
{
  "new-checkout": true,
  "button-color": "green",
  "max-items": 25,
  "api-config": {
    "retries": 3,
    "timeout": 5000
  }
}
```

The response is a flat object where each key is a flag key and each value is the evaluated result for the given context.

### Context Shapes

**Single-kind context** — use when you only need user attributes:

```json
{
  "context": {
    "kind": "user",
    "key": "user-123",
    "country": "IE"
  }
}
```

**Multi-kind context** — use when targeting both user and organisation:

```json
{
  "context": {
    "kind": "multi",
    "user": { "kind": "user", "key": "user-123", "plan": "pro" },
    "organization": { "kind": "organization", "key": "org-456" }
  }
}
```

**Empty context** — evaluates all flags with defaults only (no targeting rules match):

```json
{
  "context": {}
}
```

<Info>
  Percentage rollouts require a `key` field in the context (typically `user.key`). Without it, the evaluator cannot deterministically assign users to variations.
</Info>

## Authentication

The evaluation endpoint uses your **SDK key** (not a JWT or admin key). SDK keys start with `ff_` and are scoped to a specific project and environment.

Pass the key using the `x-api-key` header:

```
x-api-key: ff_177331b0f7adabf1b75e026762c1acc005bff9d244eff5ebe98d1aff69c2df34
```

SDK keys grant access to evaluation (`/evaluator/*`) and the ASL handshake. They cannot create, update, or delete flags.

## Error Responses

| Status | Meaning | Common Cause |
|--------|---------|--------------|
| `400` | Bad Request | Malformed JSON or missing required fields |
| `401` | Unauthorised | Invalid, expired, or revoked SDK key |
| `429` | Too Many Requests | Rate limit exceeded (check `X-RateLimit-Remaining` header) |
| `500` | Internal Server Error | Server-side issue — retry with backoff |

### Error response body

```json
{
  "error": "Invalid API key",
  "statusCode": 401
}
```

## Rate Limiting

The evaluation endpoint returns rate limit headers:

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | Maximum requests per window |
| `X-RateLimit-Remaining` | Requests remaining in current window |
| `X-RateLimit-Reset` | Unix timestamp when the window resets |

When rate limited (429), the SDK should use cached values and retry after the reset time.

## Server-Sent Events (JavaScript SDK v2)

For a persistent stream, handshake first, then open EventSource. Do not reuse a `sessionId`.

```javascript
const handshake = await fetch('https://api.flagmint.com/auth/asl-handshake', {
  method: 'POST',
  headers: { 'x-api-key': 'ff_your_sdk_key' }
});
const { data } = await handshake.json();

const context = btoa(JSON.stringify({
  kind: 'user',
  key: 'user-123',
  country: 'IE'
}));

const stream = new EventSource(
  `https://api.flagmint.com/evaluator/v2/flags/stream?sessionId=${encodeURIComponent(data.sessionId)}&context=${encodeURIComponent(context)}&platform=browser`
);

stream.addEventListener('connected', (event) => {
  const { connectionId } = JSON.parse(event.data);
  // Keep connectionId for POST /evaluator/v2/flags/context
});

stream.addEventListener('flags', (event) => {
  const { flags } = JSON.parse(event.data);
  console.log('Flags:', flags);
});

stream.addEventListener('quota_exceeded', (event) => {
  console.error('Quota:', JSON.parse(event.data));
});
```

| Step | Method | Path |
|------|--------|------|
| 1. Session | `POST` | [`/auth/asl-handshake`](/api-reference/evaluation/asl-handshake) |
| 2. Stream | `GET` | [`/evaluator/v2/flags/stream`](/api-reference/evaluation/flags-stream) |
| 3. Context (optional) | `POST` | [`/evaluator/v2/flags/context`](/api-reference/evaluation/update-stream-context) → `202`, flags on the stream |

Heartbeats are SSE comments (`: heartbeat`) and are invisible to `EventSource`.

Named stream events:

| Event | Payload | When |
|-------|---------|------|
| `connected` | `{ "connectionId": "<uuid>" }` | First frame. Store `connectionId` for context updates. |
| `flags` | `{ "flags": { ... } }` | After connect, after context re-eval, and on dashboard publish. |
| `quota_exceeded` | `429` body (`retryAfter`, optional cached `data`) | Quota exhausted; stream then closes. |
| `error` | `{ "error": "<code>" }` | The server rejects the stream after it opens (`session_id_missing`, `invalid_context`, …). |

`sessionId` is single-use (consumed on stream open, 300s TTL). Context updates return `202` and are debounced 400ms. Do not put secrets or PII in the stream `context` query parameter.

### HTTP long-polling fallback

If EventSource is blocked, the JavaScript SDK posts `POST /evaluator/evaluate` on an interval (`transportMode: 'long-polling'` or `'auto'` after SSE init fails). There is no `/evaluator/poll` endpoint.

## WebSocket (Go SDK)

The Go SDK still connects at `wss://api.flagmint.com/ws/sdk` with a `sessionId` query parameter from the same ASL handshake. Prefer the [Go transport guide](/sdks/go/transport) rather than speaking this protocol from new clients.

## Caching Behaviour

- REST evaluate may return a cached evaluation for the API key’s environment
- Open SSE (and WebSocket) connections receive dashboard publishes as soon as the rule set is reloaded
- Opening the stream and posting a context update both go through the evaluation quota guard

## Testing with curl

```bash
curl -X POST https://api.flagmint.com/evaluator/evaluate \
  -H "Content-Type: application/json" \
  -H "x-api-key: ff_your_sdk_key" \
  -d '{
    "context": {
      "kind": "user",
      "key": "test-user-1",
      "country": "IE"
    }
  }'
```

## Testing with the Flagmint SDK Tester

For visual testing without writing code, use the **Flagmint SDK Tester** — a standalone testing tool built specifically for QA and debugging.

### What is the SDK Tester?

The SDK Tester connects directly to your Flagmint API using the raw wire protocol. It doesn't use any Flagmint SDK — this is intentional, so you're testing the server contract, not the SDK's interpretation of it.

### Key Features

- 🔌 **Transport support** — SSE stream, WebSocket, and HTTP evaluate
- 🎯 **Visual Context Builder** — Add/remove context key-value pairs via UI
- 🚩 **Live Flag Display** — See all flags with real-time updates
- 📡 **Protocol Logging** — View handshake, stream events, and connection lifecycle
- ⚡ **Context Presets** — Quick setups for common scenarios (simple user, multi-context, empty)
- 📊 **Change History** — Track flag value changes over time

### Quick Start

```bash
# Clone the repository
git clone https://github.com/jtad009/flagmint-sdk-tester.git
cd flagmint-sdk-tester

# Install dependencies
npm install

# Start the development server
npm run dev
```

Open [http://localhost:5173](http://localhost:5173) in your browser, enter your API URL and SDK key, and start testing!

### Basic Workflow

1. **Configure Connection** — Enter your API URL and SDK key, choose transport (SSE or REST evaluate)
2. **Set Up Context** — Use a preset or manually add context fields (e.g., `kind: user`, `key: test-user-123`)
3. **Connect & Test** — Click "Connect" and "Send Context" to evaluate flags
4. **Verify Updates** — Change a flag in the dashboard and watch it update instantly in the tester

### QA Testing Checklist

- ✅ Flag evaluates with correct default value
- ✅ Flag respects user targeting rules
- ✅ Flag respects multi-context targeting
- ✅ Flag updates in real-time when changed in dashboard
- ✅ SSE connection is stable (handshake, `connected`, then `flags`)
- ✅ Long-polling / REST evaluate fallback works correctly
- ✅ Empty context returns expected defaults
- ✅ Custom context attributes are evaluated correctly
